# Vulgshire: code and repo audit (2026-11-21)

## Overall verdict

The project is in good shape for a prototype. The code is small (about 4,300 lines), readable and well commented. The build is clean, there are 0 npm vulnerabilities, all four scenes render headless with no console errors, and the GitHub Pages deploy is green. Nothing below is urgent. Most findings are housekeeping or "fix this before the codebase grows".

## What I checked

- `npm ci` + `npm run build`: passes (one 672 KB JS chunk, 179 KB gzipped).
- `npm audit`: 0 vulnerabilities.
- Headless render of `cloister`, `rooftop`, `bridge`, `cathedral`: all load, no page errors.
- GitHub Actions: run 1 failed (before Pages was switched on), runs 2 and 3 succeeded. Pages is live.
- Git: `main` = `d8e765f`, which includes PR #1 plus the "Add files via upload" commit. The working branch is identical to main.

## Findings

### 🟠 Medium

1. **The "one data file for names" rule is broken.** CLAUDE.md says names live in one data file, but they're split three ways:
   - `src/data/world.js` (`WORLD.districts`, `WORLD.outside`),
   - `src/data/locations.json` (`places`, `zones`),
   - scene `title`s hard-coded in each scene module (`'North River Crossing'`, `'The Great Cathedral'`, and so on).

   `WORLD.districts` isn't used by any code.
2. **The two data files disagree.** The Crownkeep is at map px `[820,170]` in world.js but `[820,168]` in locations.json. The cathedral is at `[935,255]` in one and `[945,262]` in the other. `metresPerPixel` (5.6) and `gameScale` (0.25) are also defined in both. These should come from one source.
3. **`validateWorld()` can't fail.** It only checks the hand-written `WORLD.rivers` array, so it never checks the actual geometry. The real river (`RIVER_PX` in `bridge.js`) isn't validated at all. Either make it meaningful (for example, check that each zone's rivers flow toward the lake) or drop it.
4. **Two loose images at the repo root** (`22d35ad2…jpg`, `images.jpeg`, from the "Add files via upload" commit). One is a gothic hall with a rose window and a library, the other a dark opera-house staircase. They aren't documented anywhere. If they're new mood references, move them into `reference/` with descriptive names and add a line to CLAUDE.md and `assets/README.md` saying where they came from and what licence they have. They look like found images, so they're fine as references but should never be shipped as game assets.
5. **CLAUDE.md is out of date about Pages.** It still says the repo is private and Pages needs one-time setup, but the deploy succeeded, so Pages is set up. Update that section and confirm the live URL.

### 🟡 Low

6. **Small leak on scene switch.** `loadScene` disposes the geometries under `root` but not the sky, so each sky dome's `SphereGeometry` (and the moon sprite) is never freed. It's tiny, but it grows every time you press `[` or `]`.
7. **Per-frame allocations in the camera.** `controller.updateCamera()` creates new `Vector3` and `Euler` objects every frame, so there's constant GC churn. Reuse scratch objects instead.
8. **The camera ray-march is O(steps × colliders).** About 18 steps × every collider, each frame. That's fine for now; once zones get bigger, add a simple spatial grid.
9. **`preserveDrawingBuffer: true`** on the WebGL renderer costs some performance, and Playwright screenshots don't need it. Consider removing it.
10. **Shared cached water texture.** `tex.water()` is shared between rooftop and bridge, and both write `map.offset`. It's harmless because only one scene is live at a time, but it's a trap if scenes ever coexist. Clone the texture per scene.
11. **Guards don't avoid the player.** Their moving collider shoves the monk along the bridge. That's acceptable for now, but they'll need a "stop or sidestep" behaviour, especially if stealth is added later.
12. **The URL hash isn't kept in sync.** Switching scenes with `[` `]` doesn't update `#scene`, and `hashchange` isn't listened to, so links and the back button don't follow the scene.
13. **Effects use `Math.random()`** (embers, smoke, torch phases, guards). Textures use a seeded RNG, so screenshots of the textures are reproducible, but screenshots of the effects differ slightly between runs. A seed flag would make progress shots comparable.

### 🔵 Repo hygiene

14. **The README is one line.** Anyone landing on GitHub sees nothing useful. Copy in "Running it" and the controls from CLAUDE.md, plus a screenshot and the Pages link.
15. **No quality gates.** There's no linter, formatter or tests, and CI only deploys on push to main, so PRs aren't build-checked. Easy wins: a `pull_request` build job, plus ESLint and Prettier.
16. **Playwright isn't a devDependency.** `tools/screenshot.mjs` only works where Playwright is installed globally (the cloud container). Either add it as an optional devDependency or document this in the tool.
17. **No LICENSE.** That's fine while the repo is private. Decide on one before making it public or sharing builds.
18. **Large binaries in git.** `reference/` is 19 MB and `.git` is 27 MB, mostly PNGs. That's OK for now. If more references or screenshots pile up, consider Git LFS, or keep progress screenshots smaller.
19. **The bundle is one 672 KB chunk.** `chunkSizeWarningLimit: 2000` hides the warning. That's fine for a game, but splitting scenes with dynamic `import()` would speed up the first load later.

## What's good 👍

- A clean scene contract (`build()` returns `{ root, sky, colliders, env, update }`), which is easy to extend with new zones.
- The retro pipeline is nicely contained: a low-res target, a single post pass, and the jitter patch done via `onBeforeCompile`.
- All textures are procedural, seeded and cached, so there's no licensing risk. `assets/README.md` documents this.
- Geometry is merged per material, there are only a few real point lights, and baked shade materials are used. These are sensible performance choices.
- The map → zone coordinate mapping is data-driven (`locations.json` + `annotate_map.py`).
- The documentation (CLAUDE.md) is excellent and matches the code, apart from the Pages section.

## Suggested order if you want fixes

1. Tidy the root images and update the CLAUDE.md Pages section (5 minutes).
2. Merge the names and positions into one data file and pull scene titles from it (findings 1–2).
3. Add a PR build check and flesh out the README (findings 14–15).
4. Fix the small runtime issues (findings 6, 7, 9, 12).
